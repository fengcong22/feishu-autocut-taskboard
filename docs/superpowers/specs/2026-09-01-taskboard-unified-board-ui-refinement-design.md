# Taskboard 统一流程看板 UI 优化设计

## 状态与已确认决定

本设计基于已确认的交互范围：

- 飞书学科页面隐藏“节点模式”入口，但普通 Taskboard 项目继续保留节点模式；
- 项目切换列表清理历史项目；
- 已上传卡片的 ZIP 明细默认折叠；
- 统一看板支持按流程创建、切换和保存多个流程视图；
- 不自动创建“剪辑流程”“上传流程”等业务预设看板；用户自行新建看板并选择要显示的流程；
- 每个流程列显示默认说明，并可按学科编辑显示名称和说明；
- 流程列支持调整尺寸，卡片在摘要范围内自适应；
- 流程看板支持鼠标拖拽滚动；
- 右侧“其他任务”窗口保留现状，不隐藏、不改造成其他流程窗口；
- 历史项目采用“归档优先、删除受保护”：有任务或关联数据的项目只能归档，完全空的项目才允许永久删除；
- 不删除飞书 Base、飞书子表或飞书记录。

本轮先完成设计和验收约束，不改变代码或启动服务。

## 目标

让操作人员在一个稳定的学科流程看板中完成日常浏览和拖动操作，并能用保存的流程视图分别处理剪辑和上传工作，同时减少历史项目和 ZIP 明细对页面的干扰。看板必须继续保持 Base、子表、任务和上传记录的隔离，并且不能因为 UI 调整绕过现有的任务状态、Auto-Cut 授权或上传安全边界。

## 范围拆分

这次发布包含两个有明确边界、可以分别验收的子项目：

1. **项目目录生命周期**：整理项目切换列表，提供归档、恢复和受保护的永久删除；对飞书 Base/子表沿用现有移除接口，不把它们当作普通项目删除。
2. **统一看板交互**：隐藏不适用的节点模式入口，增加可保存的流程视图和列说明，压缩 ZIP 展示，增加稳定的列布局和鼠标拖拽滚动。

两部分共享项目切换和刷新状态，因此先处理目录生命周期及选择状态，再处理看板交互，最后做整体验收。

## 现有系统边界

- `web/src/App.tsx` 负责项目选择、视图切换、任务刷新和右侧 `OtherTasksPanel` 的挂载。
- `web/src/components/UnifiedWorkflowBoard.tsx` 负责飞书学科的统一流程列、任务卡片、上传摘要和任务拖放。
- `web/src/styles.css` 负责统一看板的横向容器、列内纵向滚动和响应式布局。
- `server/database.mjs` 的 `projects` 表目前没有项目归档字段；通用 `deleteProject` 只允许空的 `temp-*` 项目。
- `server/feishu-workflow-store.mjs` 已使用 `removed_at` 管理飞书 Base/子表移除，`feishu-workflow-api.mjs` 已提供对应移除接口。
- 任务内部状态、上传状态、Bridge 事件筛选、Codex 执行和 ZIP 校验均不在本设计中重新定义。

## 用户界面设计

### 1. 飞书学科页面边界

当当前项目属于飞书学科时，顶部工具栏不再显示“节点模式”按钮，也不渲染面向普通项目的 React Flow 工作区。飞书配置仍然可从已有的“配置多维表格”入口打开，配置页面只显示当前 Base 及其子表，不混入其他 Base。

当当前项目是普通 Taskboard 项目时，节点模式入口和现有行为不变。视图记忆迁移时，如果历史值为 `workflow` 且项目是飞书学科，自动回到统一流程看板，不删除保存的普通项目视图记忆。

### 2. 流程视图、筛选与列说明

统一看板仍是同一个 `issues` 工作入口；流程视图是看板内部的显示方案，不新增独立项目、不复制任务，也不使用普通项目的 React Flow `workflow` 路由。顶部工具栏显示当前视图选择器、`新建视图` 和 `管理视图`。

每个飞书学科只自动保留一个系统视图：

- **全部流程**：显示当前统一流程中的所有列，系统视图不可改名、删除或减少流程，是首次进入和配置损坏时的安全兜底。

不自动创建“剪辑流程”“上传流程”或其他业务预设看板，也不自动填入流程筛选条件。用户通过“新建视图”从空白配置开始，自行填写看板名称、选择要显示的流程并调整顺序；例如需要剪辑或上传工作台时，由用户自行建立相应视图。用户也可以从已有自定义视图复制后再编辑。自定义视图至少保留一个可见流程，删除当前视图时回到“全部流程”。视图名称在当前学科内必须唯一并限制长度，损坏或不存在的视图安全回退到“全部流程”。

视图只保存稳定的流程内部标识（例如 `in_progress`、`uploading`），不保存本地化文字、任务、ZIP、路径、命令或密钥。新建视图不会预选业务流程；用户必须明确选择至少一个流程。流程默认按照统一看板顺序排列；用户可以在视图编辑器中调整所选流程的显示顺序，但这只是纯展示排序，不改变流程的内部归属、状态优先级、任务排序规则或拖拽目标校验。切换视图或横向滚动时，各视图的布局位置分别处理。

每个流程列标题下显示一行说明。系统提供准确的默认说明，例如“处理中：Auto-Cut/Codex 正在执行剪辑”“上传中：正在把 ZIP 复制到目标位置”。流程的显示名称和说明可以在当前学科的流程设置中编辑；系统标识保持只读，编辑文字不会改变卡片归类、Auto-Cut 执行或上传逻辑。未覆盖的学科使用系统默认文字。

视图按 Base 和学科子表独立保存。首次创建或重新启用学科时，服务器只幂等地确保该学科存在“全部流程”系统视图，不生成任何业务预设或默认筛选；后续刷新不会插入或覆盖用户创建的视图。自定义视图、默认视图以及流程名称/说明不跨学科自动共享。右侧“其他任务”窗口不受流程视图筛选影响。

任务先按既定规则归类到一个真实流程，再投影到当前视图的可见流程集合；隐藏流程只影响显示，不改变任务状态、执行、上传或飞书数据。看板顶部显示隐藏流程中的任务数，隐藏的上传失败或待处理任务需要醒目标记。隐藏数量按当前项目/学科和普通标签、负责人等筛选后、视图投影前计算，并分别显示任务数和 ZIP 数；加载失败或数据尚未同步时显示“状态待同步”，不把未知状态当成 0。搜索范围使用独立的 `activeView` / `allStages` 选项：默认只搜索当前视图，用户明确选择“所有流程”后才搜索隐藏流程；“所有流程”是搜索范围，不等于切换到名为“全部流程”的视图。搜索到隐藏任务时仍只在当前视图渲染，但在顶部显示可打开详情的“隐藏流程匹配”条目，并提供一次性显示其流程的入口；打开隐藏任务详情时不自动改动当前视图。

### 3. 项目切换与历史清理

项目切换菜单分为两个区域：

- **当前项目**：只显示未归档且仍可使用的项目；
- **已归档/历史项目**：默认折叠，展开后显示名称、类型、归档时间和关联任务数量。

这里明确区分三种“归档/删除”概念：任务归档（已有任务级能力）、飞书 Base/子表移除（已有目录能力）和 Taskboard 项目归档（本次新增的本地目录能力）。三者不能互相替代。

项目的本地可见性和远端资源生命周期分开处理：

- 普通项目使用项目级软归档。归档只影响 Taskboard 的默认列表和选择，不删除任务、附件、上传记录、聊天记录或工作区文件；可以恢复。
- 飞书子表使用已有的 `removeSubject`，飞书 Base 使用已有的 `removeBase`。移除前先按现有规则停用，随后从活动目录隐藏；本地历史任务仍保留，重新添加或刷新同一资源时可以恢复目录记录。
- 如果被移除的飞书子表或 Base 正是当前选中项目，先清理详情、面板、拖拽和滚动状态，再切换到同一 Base 的下一个可见子表或全局项目；只有完成回退后才刷新目录，避免短暂显示无上下文的旧任务。
- 禁用的飞书子表与已移除的飞书子表分开处理：禁用保留在配置目录但不接收任务，移除才从活动目录隐藏；两者都不删除本地历史任务。
- 移除或禁用只停止新的 Bridge 接入，不取消已经登记、排队或正在上传的任务；上传 worker 继续按现有租约完成或报告结果。资源暂时不在目录中时，界面忽略其实时刷新，用户重新添加/选中后再按服务器状态完整加载。
- 通用项目永久删除继续使用服务器保护规则，并扩展检查任务、附件、artifact、上传记录、聊天记录、工作流和项目摘要等关联数据。只要存在任意关联数据就返回 `PROJECT_NOT_EMPTY`，不做级联删除。
- 飞书项目不通过通用永久删除接口物理删除；页面上的“删除”对飞书资源明确显示为“移除本地目录”，并提示不会删除飞书内容。

归档、恢复和删除操作都必须在服务器端校验。操作期间禁用对应按钮，成功后清理当前项目的任务、上传、摘要、详情、上下文菜单和滚动状态，并选择下一个可用项目。失败时保留原页面并展示安全错误码对应的提示。

项目切换、Base/子表刷新或 SSE 重连期间，旧项目的请求不能覆盖新项目：切换前递增项目请求代次并中止可中止的请求，响应提交前检查项目代次和当前项目 ID。

### 4. ZIP 摘要折叠

已完成剪辑、上传队列、上传中和已上传列中的卡片默认只显示紧凑摘要，例如“`2 个 ZIP · 已上传`”。

点击摘要或展开按钮后显示去重后的 ZIP 行，每个 ZIP 行包含文件名、验证/上传状态、更新时间和必要的失败原因。上传中、失败或可重试的 ZIP 自动展开；普通已上传 ZIP 默认折叠。

搜索命中隐藏的 ZIP 文件名或包别名时，卡片显示“匹配明细”标记并临时展开相关 ZIP 行；清除搜索后恢复用户此前的折叠状态。这样用户能理解卡片为何出现在搜索结果中，同时不会把搜索行为永久写入布局偏好。

扩展状态使用 `projectId + taskId + artifactIdentity` 作为作用域，并在切换项目、删除/归档项目或任务被移出当前学科时清理。按钮必须提供 `aria-expanded` 和 `aria-controls`，支持键盘操作。明细中不显示本地绝对路径、密钥、命令或不必要的 SHA-256 信息。

artifact identity 的选择顺序固定为：有效的 `artifactId`，否则有效的上传 ID，最后使用规范化文件名与创建时间组合。相同 identity 只保留一行；状态优先级为“上传中 > 失败/排队 > 已上传”，同状态取最新记录。没有入队但已验证的 ZIP 仍计入摘要，并在展开后可见。

artifact 摘要沿用现有上传资格边界：只有 `validationStatus=verified` 的 artifact 进入可上传 ZIP 汇总；未验证、校验失败或结构无效的 artifact 不进入上传列，也不能被折叠计数伪装成可上传文件。若任务详情已有这类 artifact，继续在详情中显示其安全错误状态，不能因本次折叠改造改变上传资格。混合验证状态必须有回归测试。

### 5. 流程列尺寸与卡片布局

看板使用一个明确的横向滚动容器，列宽采用窄、标准、宽三档预设；如现有布局允许，再提供统一拖动把手调整列宽。所有列同步使用同一列宽，避免单列变化造成对齐漂移。

列高度填满可用看板区域，任务列表在列内独立纵向滚动。卡片只根据可见摘要自动适应高度：标题换行最多使用有限行数，摘要信息在空间不足时截断并通过详情面板查看完整内容。不会把所有字段直接展开到卡片，也不提供逐卡片手动高度设置。

列宽预设、卡片密度和每个 Base/学科的横向及列内滚动位置保存在本机布局设置中；刷新后恢复，切换到另一个学科时使用其独立设置。提供“恢复默认布局”操作。加载骨架、空状态和错误状态使用与实际列相同的宽度约束，避免加载完成时页面跳动。

桌面端保持现有右侧 `OtherTasksPanel` 的叠加/收起行为和可达性；布局调整不得把右侧窗口移除或改为新的流程列。窄屏继续使用现有移动端抽屉行为。

### 6. 看板鼠标拖拽滚动

交互区域按职责区分：

- 拖动看板空白区域，使用指针捕获横向平移整个看板；
- 拖动某一列任务列表的空白区域，纵向滚动该列；
- 拖动任务卡片，继续执行现有的任务阶段移动；
- 上传虚拟列（上传队列、上传中、已上传）不接受任务阶段拖放，卡片不可作为状态拖动源；
- 当前流程视图未显示的真实流程不能作为隐形拖放目标，必须先切换到包含该流程的视图；
- 卡片上的按钮、链接、重试、菜单和对话入口不启动看板滚动拖拽。

看板拖拽必须有移动阈值，以免普通点击误触发；使用 `grab/grabbing` 光标，并在 `pointerup`、`pointercancel`、Escape、项目切换和组件卸载时清理状态。拖到看板左右边缘时可触发有限的自动横向滚动，使屏幕外的流程列可达；列内纵向滚动不能吞掉有效的 `dragover/drop` 事件，目标高亮在横向滚动后仍须正确。滚轮、触控板、键盘和滚动条继续可用，作为无鼠标或触屏场景的备用方式。

任何拖放提交仍通过现有任务移动接口，服务器校验项目、任务版本和目标状态；旧项目任务、过期任务 ID 或上传列目标一律拒绝。统一看板只接受当前选中 Feishu 学科项目中、属于 `REAL_TASK_STAGES` 且在当前视图可见的任务作为可移动来源；来自“其他任务”窗口的普通任务、已归档任务和上传列来源必须拒绝，不能仅凭全局 task ID 执行移动。视图切换或隐藏列设置变化时，正在进行的拖放立即取消。

### 7. 右侧“其他任务”窗口

本次不改变该窗口的功能、入口、宽度、标签或显示位置。任务详情打开时可以暂时隐藏面板，但必须保留并恢复其打开状态、当前标签和焦点；关闭详情或通过返回/Escape 回到看板后，面板应按原状态重新挂载，不能丢失。打开任务详情、切换项目、切换看板视图、关闭面板后，面板状态和看板滚动不应导致数据串项目或焦点丢失。现有桌面叠加和移动端抽屉保持兼容。

## 数据与接口设计

### 项目生命周期

普通项目在 `projects` 表增加可空的 `archived_at` 字段；旧数据迁移为 `NULL`。项目 API 的默认列表只返回 `archived_at IS NULL`，历史列表通过显式的管理查询获取。项目响应增加 `archivedAt` 和可用于展示的项目类型/来源信息，但不返回本地机密路径以外的新敏感数据。

推荐接口契约如下：

- `GET /api/projects`：默认返回活动项目；使用受控的 `includeArchived=true` 获取历史项目；未知查询参数继续返回 400。
- `POST /api/projects/:id/archive`：归档或恢复，正文为 `{ "archived": true|false }`，服务器验证项目存在和状态冲突。
- `DELETE /api/projects/:id`：保留为永久删除，只允许符合空项目约束的普通项目；非空或飞书项目返回明确错误码。

飞书 Base/子表继续调用现有 `/api/local/feishu/workflow/bases/:baseToken` 和 `/subjects/:subjectKey` 移除接口。项目列表合并 Feishu 目录时，已移除资源不应重新出现在活动项目区；重新添加同一 URL 或刷新目录时按现有恢复语义重新显示。

### 流程视图与列展示模型

统一看板视图使用独立于普通 `BoardView` 的数据模型：

```text
UnifiedWorkflowView {
  id: string
  subjectKey: string
  name: string
  stageIds: UnifiedWorkflowStage[]
  isSystem: boolean
  revision: number
  createdAt: string
  updatedAt: string
}

UnifiedWorkflowViewsState {
  schemaVersion: 1
  defaultViewId: string
  activeViewId: string
  views: UnifiedWorkflowView[]
}

StageDisplayOverride {
  subjectKey: string
  stageId: UnifiedWorkflowStage
  zhName: string | null
  enName: string | null
  zhDescription: string | null
  enDescription: string | null
  revision: number
  updatedAt: string
}
```

同一学科的视图集合保存为版本化记录，至少包含 `schemaVersion`、`activeViewId` 和 `views`。首次创建时只写入“全部流程”系统视图；自定义视图的 `stageIds` 是显式的可见流程白名单，不使用“隐藏哪些流程”的反向列表，因此以后新增流程不会偷偷出现在已有视图里。未知、重复或损坏的流程标识在读取时丢弃并提示；如果结果为空则回退到“全部流程”。

流程名称和说明单独保存为当前学科的显示覆盖，内部流程标识始终只读。覆盖只保存纯文本：名称最多 32 个字符，中文/英文说明各最多 120 个字符，不允许 HTML、脚本或不可见控制字符；系统默认说明在没有覆盖时生效，改名或切换语言不会改变阶段计算。阶段计算顺序固定为：当前项目/学科隔离 → 按上传优先级完成一次任务归类 → 应用普通任务搜索/标签筛选 → 统计可见与隐藏任务 → 按 `stageIds` 渲染列。列徽标区分任务数量和 ZIP 数量，避免把一个任务的多个 ZIP 误读成多条任务。

流程视图只在 `boardView='issues'` 且当前项目为飞书学科时读取和写入。切换到普通项目、节点模式、列表、甘特图或 Auto-Cut 包管理页时，不应用或修改流程视图状态；返回统一看板时恢复该学科的活动视图。

命名视图和流程显示覆盖保存到 Taskboard 本地数据库，并以不可变 `subjectKey` 隔离。`defaultViewId` 是集合级字段：首次创建时指向“全部流程”，用户可以改成其他视图；任意时刻只能有一个默认视图。第一期视图属于本机 Taskboard 实例的共享配置，同一实例中的浏览器看到相同的命名视图；不做多用户私有视图和权限分层。写入使用版本号/乐观并发检查，冲突时拒绝旧版本覆盖并要求重新加载。推荐 API 契约为：`GET /api/local/feishu/workflow/views?subjectKey=...` 读取视图集合，`POST` 创建视图，`PATCH /:viewId` 使用 `{ revision, name, stageIds, defaultViewId }` 更新，`DELETE /:viewId` 删除；流程名称/说明覆盖通过同一 subject 的阶段展示接口保存，并使用相同的 revision 边界。读取旧版本中遗留的 `templateKey` 时忽略该字段，不再按模板自动生成或恢复业务视图。

视图定义可在后续共享配置中导出/导入，导入时只接受合法流程标识，不带任务数据或本地路径。学科移除时按受影响的全部 `subjectKey` 原子清除活动视图指针，并将视图和显示覆盖冻结为不可编辑但保留的历史配置；重新添加同一 `subjectKey` 时恢复它们。可恢复的普通项目归档保留视图配置，但历史项目中的视图和流程说明只读；恢复后恢复写权限。普通项目永久删除必须一并删除其视图和布局偏好。视图删除、学科移除和项目永久删除时分别清理活动指针及其关联显示状态。

### 布局状态

布局设置是浏览器本机偏好，不进入飞书单元格、任务描述、共享配置或 Auto-Cut 包 registry。布局必须按项目和流程视图分别保存，建议键格式为：

```text
taskboard.unified-board.layout.v1:<projectId>:<viewId>
```

值至少包含：

```json
{
  "columnWidthPreset": "standard",
  "cardDensity": "comfortable",
  "boardScrollLeft": 0,
  "columnScrollTop": {},
  "zipExpansion": {}
}
```

拖拽过程中的指针状态、临时拖动任务、展开中的请求和错误不持久化。

### 刷新与并发

项目切换、列表刷新、SSE 事件、revision polling、工作流选项和所有按项目发起的请求必须共享同一项目代次校验；视图切换只改变本地投影，不重新请求或写入任务状态。归档/删除成功后，前端清空该项目的本地缓存和请求引用，再刷新项目目录和 Feishu catalog。任何晚到的旧项目响应都只能被丢弃，不能重新填充看板或右侧窗口。

## 错误与安全约束

- 有关联数据的永久删除返回 `PROJECT_NOT_EMPTY`，同时提供关联数量，不能通过前端隐藏按钮绕过服务器校验。
- 已归档项目仍可在历史区域查看，但默认不接收新的工作流任务；恢复后才回到活动列表。
- 移除飞书资源只改变本地目录和监听配置，不调用删除飞书 Base/记录的 API。
- 归档或切换项目时，不中止正在运行的 Codex/Auto-Cut 任务；只停止旧项目界面的展示和刷新订阅。
- 看板拖拽不改变上传状态，不触发重复入队或重复上传。
- 流程视图筛选不改变任务状态、上传状态或 Auto-Cut 执行；隐藏流程中的异常仍通过数量和提示可见。
- 布局和折叠状态不包含工作区路径、ZIP 获取路径、上传目标路径、prompt、模型参数或密钥。

## 验收标准

### 项目目录

1. 普通空项目可归档、恢复和永久删除。
2. 普通项目只要存在任务（包括已归档任务）或任意关联记录，永久删除均被拒绝。
3. 飞书 Base/子表可从目录移除，移除后不出现在活动列表，飞书内容和本地历史任务不被删除。
4. 当前项目被归档或移除后，页面自动选择下一个活动项目；旧项目的晚到请求不会恢复旧卡片。
5. 刷新和重新连接后，活动/历史分区与服务器一致。

### 看板交互

1. 飞书学科页面没有“节点模式”按钮，普通项目仍有。
2. 首次进入只显示“全部流程”系统视图；不会自动出现“剪辑流程”或“上传流程”。用户可以从空白新建、命名、选择流程、调整顺序、复制、编辑和删除自定义视图；“全部流程”不可删除。
3. 每个学科只显示自己的视图；视图只投影流程列，不改变任务状态、Auto-Cut 执行或上传状态。
4. 流程列显示默认名称和说明，按学科修改后只改变展示文字；内部流程标识和卡片归类保持稳定。
5. 隐藏流程中的任务数量和异常可见，任务详情可以打开隐藏任务；搜索默认限制在当前视图，明确选择后才搜索全部流程。
6. 已上传卡片默认折叠 ZIP 明细，展开/收起、键盘操作、搜索和重试均正常。
7. 多个相同 `artifactId` 只显示一条摘要，状态优先级和最新时间规则稳定；未入队 ZIP 不丢失，未验证 artifact 不伪装成可上传 ZIP。
8. 列宽预设、卡片密度和滚动位置按学科及视图独立保存，恢复默认有效，加载/空状态不跳动。
9. 空白区域拖拽可横向/纵向滚动；卡片拖拽仍可移动当前视图中的真实任务；隐藏列、上传虚拟列、按钮和链接不会误触发状态移动；普通任务从右侧窗口拖向统一看板时被拒绝。
10. 右侧“其他任务”窗口仍可打开、切换标签、进入详情和关闭，详情返回后恢复原来的面板状态，且不发生跨项目数据污染。
